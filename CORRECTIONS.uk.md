## Деталі запропонованих правок

### REA-001 — fillna(0) не збережено
**Проблема:** `record.df.fillna(0)` не змінює оригінальний DataFrame.  
**Правка:** замінити на `record.df.fillna(0, inplace=True)` або `record.df = record.df.fillna(0)`.  
**Тест валідації:** створити CSV з порожньою/NaN коміркою `result`, запустити скрипт і підтвердити, що немає виключення та значення трактується як 0.

### REA-002 — match може бути None
**Проблема:** файл у `data/` за межами шаблону спричиняє `AttributeError`.  
**Правка:** відфільтрувати файли за допомогою `if match is None: continue` перед доступом до `.group()`.  
**Тест валідації:** додати дивій файл до `data/` і підтвердити, що скрипт продовжує роботу без помилки.

### REA-003 — відсутні групи спричиняють KeyError
**Проблема:** `record["active"]` / `record["inactive"]` без перевірки.  
**Правка:** перевірити, що обидва ключі існують перед подальшим виконанням; інакше вивести попередження та пропустити камеру.  
**Тест валідації:** створити теку `data/` з камерою, що має лише одну групу, і підтвердити коректну обробку.

### REA-004 — неполний README
**Проблема:** README описує лише cam1/cam2; cam3 існують у даних. Результати-hardcode.  
**Правка:** додати розділ cam3 до README (або генерувати динамічно); зберегти нотатку, що значення ілюстративні.  
**Тест валідації:** підтвердити, що README згадує cam1, cam2 та cam3.

### REA-005 — неконсистентна схема між CSV
**Проблема:** `active_cam*` мають заповнений `id`; `inactive_cam*` мають порожній `id`; `inactive_cam3` не має `id`.  
**Правка:** задокументувати варіацію у README; не змінювати дані (уникнути втрати інформації). Розглянути стандартизацію при майбутньому збиранні.  
**Тест валідації:** підтвердити заголовки всіх CSV.

### REA-006 — основа для відтворюваності та CI
**Проблема:** немає тестів, немає CI, немає `requirements.txt`, Python 3.7 EOL.  
**Правка:** додати `requirements.txt` (pandas, scipy), юніт-тести з pytest, workflow GitHub Actions, оновити `python_version` у `Pipfile` до 3.10+.  
**Тест валідації:** `pytest` проходить; workflow CI запускається при push/PR.
