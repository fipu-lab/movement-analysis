# REVERSE_ENGINEERING_REPORT — movement-analysis

## A. Загальний діагноз

### Виявлена архітектура
Мінімальний проєкт Python для статистичного аналізу руху. Немає прикладного шару, API, інтерфейсу або бази даних. Потік реалізовано одним скриптом `analysis.py`, який:

1. Читає всі файли CSV у теці `data/`, ім’я яких відповідає шаблону `(?P<type>.*)_(?P<cam>.*)_formula.csv`.
2. Завантажує кожен CSV до pandas DataFrame.
3. Групує записи за камерою (`cam`) та типом (`active` / `inactive`).
4. Для кожної камери застосовує тест Манна — Уітні (`scipy.stats.mannwhitneyu`, `alternative="greater"`), порівнюючи стовпець `result` активної та неактивної груп.
5. Виводить кількість, квантилі та результат тесту.

Немає веб-точка входу, немає маршрутів, немає frontend-компонента. Це автономний скрипт аналізу.

### Технології та залежності
- Мова: Python 3.7 (зазначено в `Pipfile`, вже завершив життєвий цикл)
- Залежності виконання: `pandas`, `scipy`
- Залежності розробки: `black`, `ipython`, `ipykernel`
- Керівник залежностей: Pipenv (`Pipfile` + `Pipfile.lock` закомічені)
- Немає `requirements.txt`, немає `setup.py`/`pyproject.toml`, немає CI.

### Деталі підтверджених проблем

**REA-004 (CONFIRMED)**: `README.md` містить аналізи лише для `cam1` та `cam2`, проте в теці `data/` містяться `active_cam3_formula.csv` та `inactive_cam3_formula.csv` (по 25 779 рядків кожен). Скрипт `analysis.py` обробив би cam3, якби виконувся, але README не згадує його. Крім того, значення `pvalue` та `statistic` в README є hardcoded (наприклад, `pvalue=0.0` для cam1), не відтворюються автоматично з коду.

Довід: `README.md:7-27` згадує лише cam1/cam2; `data/` містить 6 файлів, включаючи cam3.

**REA-005 (CONFIRMED)**: CSV не мають однієї схеми. `active_cam1/2/3` мають стовпці `timestamp,id,result` із заповненим `id`. `inactive_cam1/2` мають `timestamp,id,result` із порожнім `id` (`,,значення`). `inactive_cam3` має лише `timestamp,result` (без стовпця `id`). Скрипт читає тільки `result`, тому не ламається, але це неконсистентність даних.

Довід: заголовок `inactive_cam3_formula.csv` = `timestamp,result`; заголовок `active_cam1_formula.csv` = `timestamp,id,result`.

**REA-006 (CONFIRMED)**: Немає автоматизованих тестів, немає CI, немає `requirements.txt`. `Pipfile` зазначає `python_version = "3.7"` (завершив життєвий цикл з 2023-06-27).

### Деталі ймовірних проблем (не відтворено у поточних даних)

**REA-001 (PROBABLE)**: `record.df.fillna(0)` (рядок 16) не передає `inplace=True` і не призначає результат назад (`record.df = record.df.fillna(0)`). За замовчуванням `fillna` повертає новий DataFrame. Якщо б у `result` були `NaN`, вони б не заповнилися, і `mannwhitneyu` міг би вийти з ладу або повернути `NaN`. У поточних CSV стовпець `result` заповнений, тому не проявляється, але це прихований помилковий стан.

**REA-002 (PROBABLE)**: `match = pattern.match(fname)` (рядок 17). Якщо будь-який файл у `data/` не відповідає шаблону `.*_.*_formula.csv` (наприклад, `.DS_Store`, `README`, тимчасовий файл), `match` буде `None`, і `match.group("type")` спричинить `AttributeError`, перериваючи увесь скрипт. Фільтрації файлів або обробки виключень не існує.

**REA-003 (PROBABLE)**: Рядки 26-28 безпосередньо отримують доступ до `record["active"]` та `record["inactive"]`. Якщо у камери лише одна група (наприклад, лише `active`), виникне `KeyError`.
